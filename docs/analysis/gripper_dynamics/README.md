# RViz와 Gazebo 그리퍼 응답 차이 진단

2026-11-12. 제어 코드를 변경하지 않고 현재 설정으로 측정했다.

## 확인된 동작 경로

- RViz: `gripper_joint_publisher.cpp`가 20ms마다 stroke를 최대 50씩 갱신하고,
  네 관절 모두에 `stroke/700`의 동일한 각도를 발행한다. 물리적 추종 오차를 표시하지 않는다.
- Gazebo: `gz_scene.py`가 그 관절값을 받고 기본 20Hz로 목표를 전달한다.
  `physics_robot.py`는 URDF의 mimic을 제거하고 네 관절을 각각 힘 PID로 제어한다.
  P=5, I=0.1, D=0.1, 최대 토크 ±2Nm이며 URDF 관절 감쇠는 0.7Nm·s/rad다.
- PickPlace2 가상 그리퍼는 0.4초 대기 후 다음 단계로 진행한다.
  이 대기는 Gazebo 실제 관절 위치나 접촉 완료를 확인하는 조건이 아니다.

## 격리된 공중 개폐 시험

`measure.py`는 프로세스마다 별도 `GZ_PARTITION`을 설정하고 그리퍼만 있는 서버를 생성한다.
플랜지 고정, 그리퍼 아래 방향, 중력 활성, 판·말 접촉 없음, 물리 간격 1ms.
실제 ROS 로봇이나 사용자의 Gazebo 장면에는 명령하지 않는다.
목표는 0rad에서 0.8rad까지 약 0.3초 동안 증가시키고 유지했다.

| 명령 증가 시작 후 시간 | 목표 각도 | 실제 첫 관절 r1/l1 | 실제 둘째 관절 r2/l2 |
|---|---:|---:|---:|
| 0.4초 | 0.8rad | 약 0.605rad | 약 0.599rad |
| 0.6초 | 0.8rad | 약 0.749rad | 약 0.744rad |
| 0.8초 | 0.8rad | 약 0.790rad | 약 0.786rad |
| 1.0초 | 0.8rad | 약 0.801rad | 약 0.797rad |

모든 관절이 목표 오차 0.01rad 이내에 처음 들어온 시간은 약 0.85초다.
전체 시험에서 관절 간 각도 차이는 최대 0.00705rad(약 0.404°)였다.
마지막 1초 평균은 r1/l1=0.80537rad, r2/l2=0.80209rad였다.
좌우는 이 대칭·무접촉 시험에서 동일하게 움직였다.

## 원인 판단과 한계

1. **실제 응답보다 짧은 고정 대기**가 확인됐다. 다음 팔 동작이 시작돼도
   Gazebo 손가락은 계속 닫히거나 열릴 수 있다.
2. **목표 속도와 토크·감쇠 설정이 맞지 않는다.** RViz 발행기의 최대 목표 변화는
   약 3.57rad/s다. 해당 속도에서 URDF의 점성 감쇠만으로 약 2.5Nm가 필요하지만,
   현재 Gazebo 제어기는 최대 2Nm만 출력한다. 중력·가속·접촉 부하도 별도로 존재한다.
3. **관절 연동이 없다.** 실제 기구를 단순화한 mimic이 제거돼 각 관절이 독립적으로
   접촉 반력을 받는다. 손끝 관절이 다른 관절보다 밀리는 현상을 허용하는 구조다.
   다만 이번 공중 시험의 약 0.4° 차이만으로 사용자가 본 큰 변형을 설명할 수는 없다.
4. **관성 모델 검증이 필요하다.** 그리퍼의 서로 다른 부품 모두 동일한 대각 관성
   1e-6kg·m²를 사용한다. 형상·질량 기반 검증 없이 이를 실제 관성이라고 볼 수 없다.

13.766mm 장착 간격은 고정 조인트의 위치이며 위 동적 응답 지연의 원인이 아니다.
단, 형상 위치가 바뀌므로 판과의 접촉 시점에는 영향을 준다.
이번 시험은 팔 고정·공중 개폐이므로 팔 이동 중 흔들림 및 판 접촉 시 변형은
직접 재현·확정하지 않았다. 사용자 장면의 실행 프로세스·토픽은 진단 당시 확인되지 않았다.

개선 순서는 Gazebo 실제 상태에 근거한 완료 판정(접촉 정지도 구분),
토크·감쇠·목표 속도 정합, 물리 엔진이 계산하는 기구 연동 제약과 관성 모델 검증이다.
위치 강제 설정이나 물체 순간이동으로 해결하지 않는다. 이번 진단에서 제어 설정은 수정하지 않았다.
