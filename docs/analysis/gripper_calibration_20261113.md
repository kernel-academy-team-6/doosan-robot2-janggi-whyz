## 적용된 계산

너비→그리퍼 명령과 명령→예상 너비는 **실측 너비표를 구간 선형 보간**한다.
원 피팅만으로 명령과 너비 사이의 관계가 정해지지는 않는다. 원은 너비와 플랜지 높이의 관계를 정하므로,
명령 변환에는 같이 측정한 명령별 너비를 사용한다. 이는 fit.json의 `command_width_interpolation` 방식과 같다.
UI 대국, PickPlace2 실행기, 같은 geometry 모듈을 쓰는 TCP 시험 도구에 적용된다.
원시 명령 700 등을 보내는 측정 도구는 지정한 원시 명령을 그대로 보낸다.

| 항목 | 새 값 |
|---|---:|
| 반폭 중심 a | 4.397665870770506mm |
| 0 기준 상대 Z 중심 b | −28.617600697646548mm |
| 반지름 R | 56.30239001501211mm |
| branch | +1 |
| 명령 0 실측 너비 | 105.9mm |
| 명령 700 실측 너비 | 6.3mm |
| 방사 방향 피팅 RMSE | 0.0400796955mm |

방사 방향 RMSE는 너비 명령 오차나 실제 파지 정확도 전체를 뜻하지 않는다.
그리퍼 명령은 정수로 반올림하므로 보간값에 양자화 오차가 생긴다.

기존 API의 허용 범위 6~106mm는 유지하되 실측 끝점 밖의 작은 구간은 끝 명령으로 포화한다.
6mm를 요청하면 700을 보내며 예상 너비는 실제 측정에 맞게 6.3mm로 반환한다.

## 상대 높이의 기준 변환

이번 원 데이터는 명령 **0에서 플랜지 Z=102.6717453mm를 기준**으로 했다.
명령 700에서 Z=130.2759094mm이며 실측 상대 높이는 +27.6041641mm다.
따라서 측정 행 자체를 700 기준으로 환산하려면 각 상대 Z에서 **27.6041641mm**를 빼면 된다.
절대 플랜지 좌표 102.67mm를 TCP 길이로 쓰거나 160mm에 더하지 않는다.

피팅 곡선은 실측점과 작은 잔차가 있으므로, 피팅 함수를 사용할 때는 피팅한 기준점 예측값을 뺀다.

```text
f(w) = b + sqrt(R² − (w/2 − a)²)
z_0(w)   = f(w) − f(105.9)
z_700(w) = f(w) − f(6.3) = z_0(w) − z_0(6.3)
```

- `fitted_flange_z_from_open(w)`는 `z_0(w)`, 105.9mm에서 정확히 0.
- `fitted_flange_z_from_closed(w)`는 `z_700(w)`, 6.3mm에서 정확히 0.
- 피팅으로 계산한 전체 높이 변화량은 약 **27.7818987mm**.
- 원래 피팅식의 700 기준 Z 중심은 약 **−56.2885641mm**로 환산된다.
- 넓게 벌린 쪽은 700 기준 플랜지 높이가 음수다. 부호를 뒤집지 않았다.
- 두 기준에서 임의의 두 너비 간 높이 차이가 동일한지 테스트했다.

**이번 변경으로 자동 Z 보정을 추가하지 않았다.** 현재 실행기의 `tcp_length()`는 기존 요구대로
너비와 무관하게 160mm를 반환한다. 새 곡선 함수는 기준까지 환산해 준비했으며,
실제 팔 명령에 높이 보상을 적용하는 것은 별도 동작 변경이다.
카메라·판 보정의 222mm와 Gazebo 손가락 형상·700→각도 매핑도 이번에는 수정하지 않았다.

## 적용과 검증

`janggi_pick_place2` 패키지를 재빌드했다. 기존 실행 중인 Python 프로세스는 이전 모듈을 보유하므로
UI 또는 standalone 실행기를 다시 실행해야 한다. 새 터미널에서는 기존처럼 환경을 source한다.

```bash
cd ~/doosan_janggi_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
```

PickPlace2·TCP 시험·측정 도구의 관련 테스트 **130개 통과**.
검증 중 실제 로봇 이동이나 그리퍼 작동 명령을 보내지 않았다.
