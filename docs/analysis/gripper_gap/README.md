# Gazebo 그리퍼 개도와 실측 모델 W(c) 일치 — 2026-11-14

## 변경 범위

Gazebo의 `PhysicsRobot` 입력 변환과 Gazebo 손가락 서보만 변경했다.
실제 장치에 전송하는 0~700 명령, C++/Python ROS 관절 퍼블리셔와 RViz 표시,
실물 시리얼/DRFL 제어, 팔 제어기, 질량/관성, URDF 장착 간격과 TCP 계산은 변경하지 않았다.

기존 ROS 표시용 `q=c/700`을 Gazebo도 그대로 사용했다.
현재 CAD는 q=0에서 틈이 약 106.9268mm이고 q=1에서 약 13.578mm이므로,
명령 700의 모델 목표 6.12935mm와 큰 차이가 있었다.
실물 원호 각도와 CAD 관절 원점/링크 길이가 달라 θ(c)를 그대로 관절각으로 사용해도 정확히 맞지 않는다.

## 새 변환

`src/janggi/robot_game/gripper_gap.py`는 공통 실측 모델 함수
`janggi_pick_place2.geometry.width_from_command(c)`를 직접 사용한다.

```text
W(c) = 2*(4.446124 + 56.302390*cos(0.532602 + 0.00151819*c))  [mm]
CAD W(q) = 2*(4.1 + 49.3634*cos(q) - 28.5*sin(q))           [mm]
R_CAD = hypot(49.3634, 28.5)
phi_CAD = atan2(28.5, 49.3634)
q(c) = acos((W(c)/2 - 4.1)/R_CAD) - phi_CAD
```

CAD 값은 현재 URDF의 관절 원점과 r2/l2 STL의 안쪽 평면 위치에서 얻었다.
`4.1 = 8.0 − 3.9mm`는 링크 장착 원점과 안쪽 패드 면의 차이다.

ROS 피드백의 손가락 합성 목표 c/700을 읽고 c를 복원한 뒤 Gazebo에서만 q(c)로 변환한다.
팔만 포함한 후속 메시지가 이미 변환한 손가락 각도를 다시 변환하지 않도록 새 손가락 항목만 처리한다.
이 경로는 실제 모터 피드백을 보정하거나 실제 명령을 바꾸는 코드가 아니다.

| c | 목표 너비(mm) | Gazebo 목표 관절각(rad) |
|---:|---:|---:|
| 0 | 105.900000 | 0.017742364 |
| 200 | 84.366498 | 0.315507619 |
| 400 | 55.927868 | 0.615221454 |
| 619 | 19.958576 | 0.943867873 |
| 700 | 6.129353 | 1.065361709 |

기존 관절 범위 0~1.101rad 안이다. 기존 8 stroke/20ms 애니메이션에서
변환된 관절 목표 속도가 0.65rad/s 제한을 넘지 않는지도 테스트했다.

## 실제 물리 패드 간격 검증

`calibration_validation.py`는 별도 `GZ_PARTITION`의 headless Bullet Featherstone에서
로봇팔 없이 고정 장착된 그리퍼 하나를 실행한다. ROS/DRFL/실제 장치 연결은 없다.
실제 `PhysicsRobot._on_js()`를 거쳐 변환한 목표를 Gazebo 네이티브 토크 제어기에 보냈다.
상태를 강제 지정하지 않고 중력·관성·mimic 제약을 유지했다.

측정은 계산식으로 너비를 재출력한 값이 아니다.
Gazebo의 실제 r2/l2 링크 pose와 원본 STL 패드 사각형을 사용해 표면 간 최단거리를 계산했다.
`tools/gazebo_gripper_gap.py`의 직접 측정 함수를 사용했다.

기존 손가락 PID(5, 0.1, 0.03)에서는 중력에 의한 유지 오차로 최대 약 0.845mm 좁게 측정됐다.
Gazebo 손가락 PID를 **(50, 0.1, 0.3)**으로 조정한 뒤 아래 결과를 얻었다.
최대 출력 ±2Nm, 속도 0.65rad/s, mimic 제약은 그대로다. 팔 PID/게인은 바꾸지 않았다.

| c | 모델 목표(mm) | 실제 패드 간격(mm) | 오차(mm) |
|---:|---:|---:|---:|
| 0 | 105.9000 | 105.8221 | −0.0779 |
| 200 | 84.3665 | 84.2688 | −0.0977 |
| 400 | 55.9279 | 55.8385 | −0.0894 |
| 619 | 19.9586 | 19.9053 | −0.0532 |
| 700 | 6.1294 | 6.0935 | −0.0359 |
| 350 | 63.5513 | 63.4574 | −0.0939 |
| 0 재개방 | 105.9000 | 105.8237 | −0.0763 |

각 단계 4초 동작 중 마지막 1초를 측정했다. 최대 절대 오차는 약 **0.098mm**였다.
정지 구간 흔들림 0으로 기록된 구간은 물리 엔진의 정지/수면 동작도 포함하며 무한 정밀도를 뜻하지 않는다.
시험은 물체를 잡지 않은 공중 개폐다. 물체 접촉 시 목표 각도까지 닫히지 않는 것은 정상적인 물리 반응이다.
Bullet collision margin은 패드 표면의 기하학적 간격 측정에 포함하지 않는다.
이 작업은 벌림 너비를 맞춘 것이며 CAD의 절대 팁 높이/장착 길이를 실물 H(c)와 동일하게 재설계한 것은 아니다.

상세 결과: `calibration_results.json`. 이전 PID 비교 결과는 `before_servo_calibration_results.json`.

## 적용

Gazebo를 종료하고 기존 시뮬레이션 launch를 다시 실행해야 새 모델/제어기가 적용된다.
이번 변경은 Python이므로 colcon 재빌드는 필요 없다. 실제 장치 통신 노드를 재빌드할 필요도 없다.
UI만 재시작하면 이미 실행 중인 Gazebo 모델의 제어기 값은 바뀌지 않는다.

기존 실행 환경에서 직접 확인:

```bash
cd ~/doosan_janggi_ws
./tools/measure_gazebo_gripper.sh
```

격리 검증 재현(실제 장치 연결 없음):

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash
python3 docs/analysis/gripper_gap/calibration_validation.py
```
