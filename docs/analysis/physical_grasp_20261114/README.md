# Gazebo 물리 파지·팔 떨림 수정 — 2026-11-14

수정 범위는 Gazebo의 물리 모델·제어·완료 확인이다. 실제 두산 제어기, 실물 그리퍼 시리얼 통신,
실물의 4점 높이 보정, W(c)/H(c), 닫힘 너비 20/26/32mm는 유지했다.
시험은 모두 별도 `GZ_PARTITION`에서 진행했고 실제 로봇이나 사용자의 실행 중인 Gazebo에 이동 명령을 보내지 않았다.

## 확인한 원인

1. **손끝 길이 불일치.** `gripper_mount_offset_mm:=0`의 CAD 손끝은 c=700에서 J6 플랜지로부터
   144.990555mm인데 명령은 160.368101mm를 사용했다. 약 15.377546mm 위에서 닫히는 구조였다.
   기본 장착 간격 13.766mm에서도 약 1.611546mm가 남아 6~8mm 두께의 말 파지에 영향을 준다.
   Gazebo 생성 모델만 고정 어댑터를 15.377546mm로 맞춘다. 원본 URDF/Xacro 장착값,
   RViz/실물 TF, 카메라 보정과 TCP 계산에는 이 값을 더하지 않는다.
   이 때문에 **Gazebo 생성 모델의 장착 간격은 입력 URDF 장착값과 달라질 수 있다.**
   기준은 `simulation_geometry.calibrated_mount_mm()`이고, c=0~700에서 수식상 손끝 높이 잔차는 0.12mm 미만이다.
   공중 개도의 실제 오차는 별도 동역학의 영향을 받으며 이 0.12mm는 동적 위치 정확도 보장이 아니다.

2. **접촉면과 높은 강성의 결합.** 공중 개도만 확인했던 P=50, ±2Nm 설정은 접촉 후 파지 유지 검증을 통과하지 못했다.
   얇은 말의 복셀 기반 convex decomposition, 손가락 전체 STL의 convex hull, 1ms 물리 간격에서
   말이 밀리거나 올라간 직후 이탈했다. 각 설정을 따로 바꾼 시험도 다수 실패했다.
   정확한 평면 패드, 분석적으로 같은 팔각형을 이루는 기본 충돌체, 낮은 구동 강성,
   0.5ms 스텝을 **함께 적용한 설정**에서 세 크기의 파지·운반·해제를 확인했다.
   하나의 변경만으로 모든 문제가 해결됐다는 결론은 아니다.

3. **위치 오차 미분의 충격.** Gazebo는 1~2kHz로 계산하지만 에뮬레이터 피드백은 50Hz,
   Python 목표 전달은 명목 200Hz다. 기존 PID의 D(error)는 목표 갱신·통신 지연 때 속도 잔진동을 만들었다.
   같은 경로·입력 중단 조건에서 실제 속도 오차에 감쇠를 거는 표준 제어기가 더 작은 잔진동을 보였다.

4. **완료 시점 불일치.** 기존 가상 백엔드는 에뮬레이터의 완료와 그리퍼 고정 대기만 사용했다.
   Gazebo가 실시간보다 느리거나 접촉으로 늦어져도 다음 단계가 시작될 수 있었다.
   이제 실제 Gazebo 관절의 위치·속도가 안정된 후 다음 동작으로 넘어간다.

## 적용한 물리 설정

- 시각적 사진 스킨·말 크기는 그대로: 소형 22×6mm, 중형 28×7mm, 궁 34×8mm (최소 너비×두께).
- 말 충돌체: 길이 W, 폭 `W*tan(pi/8)`, 높이 T인 박스 4개를 0/45/90/135°로 배치한다.
  합집합은 정팔각기둥과 정확히 같다. 질량·관성은 중복 박스 부피의 합이 아닌 원래 팔각기둥으로 계산한다.
  메시 복셀화나 충돌 margin을 고려한 임의의 XY/Z 축소가 필요 없다.
- 손가락 패드: 원본 STL 평면과 같은 26×20mm 면, 10mm 두께의 박스.
  그 뒤의 지지 부분도 별도 박스이며 렌더링 CAD는 유지한다.
- 그리퍼 P/I/D = **10 / 0.1 / 0.3**, 모터 출력 **±0.3Nm**, 적분 출력 ±0.15Nm.
  URDF의 2Nm 상한보다 작은 시뮬레이션용 출력 제한이며 제조사 정격 토크가 아니다.
- 일반 마찰: 손가락 1.0, 말 0.8 유지. Bullet 경로가 기본값을 spinning friction으로 직접 전달하므로
  명시적 회전마찰 0을 사용한다. 물리적 부착, 위치 강제 설정, 목적지 스냅은 없다.
- 기본 물리 스텝 **0.0005s**. Bullet native mimic 제약과 중력은 유지한다.
- 판 표면 −20mm, 팁 목표 −18mm 유지. 실물의 기울기 보정은 Gazebo에 적용하지 않는다.

## 팔 제어와 타이밍

이미 설치된 Gazebo `JointTrajectoryController`로 위치 PI + 속도 오차 P + URDF 중력 피드포워드를 사용한다.
최근 철회한 강한 게인 그대로의 재적용이 아니라, 아래의 낮은 강성을 동일 경로에서 다시 비교해 선택했다.

| 축 | 위치 Kp | 위치 Ki | 속도 Kv |
|---|---:|---:|---:|
| J1 | 600 | 5 | 35 |
| J2 | 900 | 10 | 50 |
| J3 | 700 | 10 | 30 |
| J4 | 150 | 2 | 4 |
| J5 | 120 | 2 | 3 |
| J6 | 50 | 1 | 1 |

각도 rad·시간 s·토크 Nm 기준. 위치 D=0, 속도 I/D=0.
출력 예산은 위치 50% + 속도 15% + 중력 35%로 URDF 토크 한도를 넘지 않는다.
실제 두산의 비공개 모터 게인을 복제한 설정은 아니다.

- 35ms/3차 보간은 유지한다. 실제 Gazebo joint-state의 simulation time 진행량으로 경로를 재생해
  낮은 RTF에서 벽시계 기준의 수초 경로가 더 짧은 물리 시간으로 압축되지 않게 한다.
- 버퍼는 최대 8192개. 아직 재생하지 않은 이동을 건너뛰지 않는다.
  물리 팔이 최신 목표에서 멈췄고 남은 버퍼도 같은 정지 좌표뿐일 때만 중복 정지 구간을 정리한다.
- `/dsr01/gazebo/joint_states`: Gazebo에서 측정한 관절 위치·속도, 명목 50Hz(simulation time).
- 가상 팔: 에뮬레이터 완료 후 6축 모두 오차 0.35° 미만·속도 2°/s 미만 상태를 0.1초(simulation time) 확인한다.
- 가상 그리퍼: 기존 stroke 전달 대기 후 실제 개도 근접·저속 상태를 0.1초 확인한다.
  접촉으로 목표보다 덜 닫힐 수 있어 개도 허용차는 3mm다. 이는 **집기 성공 판정이 아닌 동작 안정 확인**이다.
  영상 기반 재시도와 사용자의 정지 기능은 유지한다.
- UI `--source gazebo`에서 활성화한다. 독립 액션 서버 YAML의 `virtual_physics_feedback: true`도 같은 기능이다.
  Gazebo 없는 에뮬레이터 단독 시험은 launch의 `virtual_physics_feedback:=false`로 끌 수 있다.
- 실제 백엔드는 이 토픽을 기다리지 않고 기존 시리얼 명령/2초 대기 방식을 사용한다.

## 느린 시뮬레이션과 공중 개도 확인

`slow_timing.json`: real-time factor 0.4에서 벽시계 3초짜리 홈 경로를 공급했다.
물리 완료는 벽시계 **7.512초 / 시뮬레이션 3.009초**에 확인됐다.
가장 빠른 축은 약 84.710°/s였다. 에뮬레이터 종료(3초)에 UI가 곧바로 다음 동작을 실행하지 않았고,
물리 시간 기준 경로가 1.2초로 압축되지 않았다. 정지 중복 버퍼 정리는 미재생 이동을 버리지 않는 조건으로 단위 검증했다.

`calibration_results.json`: 최종 낮은 강성으로 7회 공중 개도를 실제 패드 포즈에서 계측했다.
4초 유지 조건에서 모델 대비 최대 차이는 **0.465mm**, 마지막 1초 흔들림은 최대 약 **0.0051mm**였다.
목표 W(c)는 유지했지만 물리 서보가 완벽히 같은 폭을 강제하는 것은 아니다.
이전 높은 P=50 설정의 0.1mm 이내 공중 오차보다 커졌고, 접촉 안정성과 교환한 부분이다.

동일 경로의 이동 위치 오차가 모든 축에서 줄어든 것은 아니다.
예를 들어 J1의 이동 RMS 오차는 약 0.034→0.047°, J6는 0.071→0.087°로 소폭 늘었다.
속도 잔진동과 파지 중 안정성을 함께 확인해 선택했다.
관련 Python 검사 **243개 통과**, `janggi_pick_place2` 빌드 완료.
중간 진단의 큰 접촉 추적은 정리하고 핵심 원인 진단 추적만 gzip으로 보관했다.
기본 재현 스크립트는 접촉 집계만 저장하며 `--contact-trace`를 명시할 때만 큰 원시 추적을 저장한다.

## 실행 반영

`janggi_pick_place2` 패키지 빌드를 완료했다. 실행 중인 Gazebo/UI를 종료하고 새 터미널에서:

```bash
cd ~/doosan_janggi_ws
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ros2 launch src/janggi/robot_game/sim_gazebo.launch.py gripper_mount_offset_mm:=0
```

다른 터미널에서는 같은 setup을 source한 뒤 기존 UI 명령을 사용한다.
서버·장면 프로세스를 함께 다시 시작해야 새 충돌체·제어기·물리 스텝이 생성된다.

```bash
./janggi/realtime_ui/run.sh --source gazebo --model-mode hybrid --robot --ns dsr01
```

재현(실제 로봇 연결 없음): ROS와 install 환경을 source한 상태에서
`python3 docs/analysis/physical_grasp_20261114/validate_robot.py --kind soldier`를 실행한다.
`cha`, `king`도 가능하다. `validate_timing.py`는 `robot_soldier.sdf` 생성 후 실행한다.
각 스크립트는 자신이 생성한 별도 Gazebo 서버만 종료한다.
