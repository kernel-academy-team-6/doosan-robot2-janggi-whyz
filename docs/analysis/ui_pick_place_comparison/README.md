# UI와 직접 픽앤플레이스의 명령 차이

사용자가 같은 X/Y/Z, yaw=0 직접 명령에서는 충돌하지 않고 UI에서 충돌함을 보고했다.
사용 중인 로봇에 이동/개폐/정지 명령은 보내지 않고 코드와 위치 조회로 비교했다.

확인된 차이:

| 항목 | 수정 전 UI | 직접 액션 서버 | 수정 후 UI |
|---|---|---|---|
| yaw | 보정 A-C = 40.0203° 자동 적용 | 입력 0° | 기본 0°, 명시적 `--pick-yaw`만 반영 |
| 속도/각속도 | 기본 100mm/s, 30°/s | YAML 120mm/s, 60°/s | YAML 기본값 공유, 명시적 직선 속도만 override |
| 가상 그리퍼 | position_cmd, 1초 대기 | stroke, 0.4초 대기 | 같은 runtime factory의 stroke, 0.4초 |
| 관찰 자세 파일 없을 때 | [0,0,90,0,90,90] | YAML home [-90,8.5645,113.1065,0,58.3289,90] | YAML home 사용 |

두 관찰 자세의 URDF FK 플랜지 Z는 각각 약 405mm와 205mm다.
직접 실행 후 현재 위치를 읽은 결과도 [406.5873,-74.6834,205.00035,...]였다.
추가 Z 보정이 합산된 경로는 발견하지 못했다. 집기 목표 Z=-20mm이면 플랜지 Z=140mm로 계산한다.

이 차이들은 명령의 불일치를 확인한 것이며, 어느 하나가 사용자 장면 충돌의 유일한 원인이었다고
실제 재현 검증한 것은 아니다. 입력·시작 높이를 동일하게 한 회귀 테스트에서는 UI 어댑터와
직접 PickPlaceExecutor가 동일한 이동/개폐 명령을 만드는지 검사한다.

추가 기록:
- UI 세션 `robot_commands.jsonl`에 원본 팁 목표, 실제 move_line 요청, 개폐 명령, 관찰 move_joint를 저장.
- 말 폭은 UI가 인식한 종류의 대표값을 사용하므로 직접 명령의 --width 27과 다를 수 있다. 로그로 확인 가능.
- 물리 PID 추종과 실제 접촉은 별도 문제다. 이번 변경으로 충돌이 완전히 해결됐다고 검증한 것은 아니다.
