# 그리퍼 너비·플랜지 높이 실측 보정

그리퍼 명령을 **700, 650, 600, …, 50, 0**으로 바꾸면서 같은 바닥에 손가락을 접근시키고,
자로 잰 **전체 안쪽 간격**과 실제 **6번 플랜지 Z**를 기록한다. 총 15개 점이다.
명령값 0에서 기록한 플랜지 Z를 높이 0으로 정하고, `(실측 너비/2, 상대 플랜지 Z)`를 원에 피팅한다.
기존 게임 UI, 카메라 보정 파일, 160/222mm 오프셋이나 TCP 설정을 자동 변경하지 않는다.

## 실행

실물 로봇 드라이버와 갱신된 `gripper_service_node`를 먼저 실행한 뒤:

```bash
cd ~/doosan_janggi_ws
./tools/run_gripper_height_calibration.sh --backend real --ns dsr01
```

스크립트가 ROS Jazzy와 workspace 환경을 불러온다. 시스템 Python의 Tk, NumPy, SciPy,
Matplotlib을 사용하며 인식용 모델이나 RealSense가 필요하지 않다.
다른 게임 UI가 같은 팔에 이동 명령을 보내는 동안에는 동시에 조작하지 않는다.

가상 로봇 드라이버/그리퍼로 연결하려면 `--backend virtual`, 로봇 없이 UI만 연습하려면:

```bash
./tools/run_gripper_height_calibration.sh --backend mock
```

mock은 가짜 좌표와 명령만 기록한다. 실제 너비나 바닥을 자동 생성하지 않는다.
mock 결과는 실제 하드웨어 보정에 쓰는 측정이 아니다.

## 측정 순서

1. **연결**: 현재 모드, unnamed/default 플랜지 TCP, 로봇·그리퍼 연결을 확인한다. 연결 자체로 움직이지 않는다.
2. **X/Y 입력 → 현재 Z 유지 · 자세 맞춤 + XY 이동**: 현재 플랜지 XYZ에서 방향을 먼저 맞춘 뒤 같은 Z에서 XY로 간다.
   로봇 베이스 기준 `[A,B,C]=[0°,180°,0°]`이며 플랜지 +Z축은 아래를 향한다.
   현재 URDF의 그리퍼 Rz(90°) 장착 기준으로 손가락 개폐 방향이 베이스 X축, 개폐면이 XZ 평면이다.
   다른 장착 방향을 쓴다면 이 자세 정의도 바꿔야 한다.
3. **Z 이동량 입력 → 위로/아래로**: 양수 mm 값을 입력한다. `0.1`, `0.05`, `0.125` 등 소수점 가능하다.
   실제 현재 플랜지 Z를 읽어 위로는 더하고 아래로는 뺀다. 자동 접촉 감지나 바닥 탐색은 하지 않는다.
4. **보정 시작 (700)**: Z는 자동으로 바꾸지 않고 그리퍼에 정확히 700을 보낸다.
5. Z를 조절해 같은 바닥에 닿기 직전까지 접근한다. 자로 손가락 안쪽의 전체 간격을 mm로 입력한다.
6. **기록하고 다음**: 새로 읽은 실제 플랜지 자세와 입력 너비를 CSV에 먼저 저장한 뒤 정확히 650을 보낸다.
7. 같은 방법으로 0까지 진행한다. 0에서도 Z를 맞추고 너비를 입력한 다음 **기록하고 다음**을 눌러야 끝난다.
8. 모든 점의 상대 높이를 계산하고 원 피팅, PNG 그래프, JSON, 보간표, HTML 결과를 자동 저장한다.

XY는 첫 측정 이후 그 위치로 고정한다. 다른 위치로 옮겨 바닥 기울기를 높이 변화로 섞지 않기 위해서다.
현재 좌표 표시와 기록은 **로봇 베이스 기준 6번 플랜지**다. 팁 좌표로 환산하거나 160/222mm를 가산하지 않는다.
입력 너비는 자로 직접 잰 값이다. 이전 모델의 너비 추정값을 측정값으로 채워 넣지 않는다.
그리퍼의 정수 명령도 너비→명령 변환 없이 그대로 전송한다.

**현재 단계 그리퍼 적용**은 재개·명령 실패 시 현재 단계 값을 다시 보낼 때 쓴다.
**이전 측정 다시하기**는 마지막 행을 취소하고 그 단계의 명령을 다시 적용한다.
**로봇 정지**는 진행 중인 팔 이동에 정지를 요청하고 다음 자동 단계를 중단한다.
이미 전송된 그리퍼 명령의 물리 동작을 되돌리는 기능은 아니다.

직선/회전 속도는 이 도구 전용 기본값 10mm/s, 20mm/s², 10°/s, 20°/s²다.
게임 UI의 속도를 바꾸지 않는다. 실행 인자로 변경할 수 있다:

```bash
./tools/run_gripper_height_calibration.sh --velocity 20 --acceleration 40
```

## 저장과 재개

기본 저장 위치:

```text
tools/calibrations/gripper_height/YYYYMMDD_HHMMSS_ffffff/
  measurements.csv     # 원본 명령·전체 너비·절반 너비·실제 플랜지 자세·상대 높이·시간
  session.json         # backend, namespace, 기준 Z, 다음 단계
  fit.json             # 원 중심, 반지름, 가지 부호, 기준 너비/Z, 방사 RMSE/최대 오차
  fit_residuals.csv     # 각 측정점의 높이 잔차
  lookup.csv           # 명령 0~700의 보간 너비 및 0 기준 높이 변화
  fit.png              # 높이 변화 곡선 및 원 피팅 그림
  report.html          # 식·오차·표·그래프 설명
```

0을 아직 기록하지 않았다면 CSV의 상대 높이는 비워 둔다. 0을 기록하면 전체 행을 갱신한다.
측정 행이 바뀌면 이전 피팅 파일을 지워 과거 결과가 최신인 것처럼 남지 않게 한다.
원본 측정은 단계마다 저장되므로 중간에 종료해도 재개할 수 있다:

```bash
./tools/run_gripper_height_calibration.sh --backend real --ns dsr01 \
  --resume tools/calibrations/gripper_height/세션/measurements.csv
```

재연결 후 필요한 경우 높은 위치에서 기록된 XY로 돌아가고 **현재 단계 그리퍼 적용**을 누른다.
기록과 다른 backend/namespace로 이어 쓰지 않는다.
별도 저장 폴더는 `--output /원하는/폴더`로 지정한다. 기존 CSV가 있는 폴더는 덮어쓰지 않는다.

로봇·GUI 없이 저장된 데이터만 다시 피팅하려면:

```bash
/usr/bin/python3 tools/gripper_height_tool.py --fit /경로/measurements.csv
```

## 피팅과 높이 변화 해석

`u`는 그리퍼 명령, `w`는 자로 잰 전체 너비, `Z`는 실제 플랜지 높이다.

```text
x = w / 2
h = Z(u) - Z(u=0)
(x - a)² + (h - b)² = R²
```

중심 `(a,b)`와 반지름 `R`을 자유 변수로 둔다. 측정점에서 원까지의 방사 방향 거리를 최소화하는
비선형 최소제곱(geometric least squares)을 사용한다. 중심 X를 임의로 0으로 고정하지 않는다.
중복점·거의 직선인 점·원 양쪽 가지에 걸친 데이터는 높이 함수를 확정하지 않고 오류를 표시한다.
측정 CSV는 피팅이 실패해도 남는다.

```text
F(w) = b + branch × sqrt(R² - (w/2 - a)²)
H(w) = F(w) - F(w_at_u=0)
```

피팅 오차 때문에 원이 기준 점을 정확히 통과하지 않을 수 있어, `H`는 기준 너비에서 다시 빼서
명령값 0의 보정 높이를 정확히 0으로 만든다. 동일한 바닥에서 측정했다면 `H`는 열린 상태 대비
손가락 길이 변화로 해석할 수 있다. 그리퍼 폭을 바꿀 때 같은 팁 높이를 유지하기 위한 플랜지 변화는:

```text
Z_new = Z_old + H(new_width) - H(old_width)
```

닫을수록 손가락이 길어지는 측정 결과라면 닫을 때 플랜지를 올려야 하므로 양의 변화가 나온다.
`lookup.csv`의 명령값별 너비는 실측한 15개 점 사이의 **선형 보간**이다. 실제 모터 피드백은 아니다.
실측 너비 범위 밖에는 외삽하지 않는다. 바닥 접근 판단, 자의 정밀도, 관절 추종 오차가 피팅에 포함되며
원의 낮은 RMSE만으로 실제 일정한 팁 높이를 검증한 것은 아니다.
