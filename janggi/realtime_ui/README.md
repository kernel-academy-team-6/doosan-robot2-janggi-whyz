# realtime_ui — 장기말 실시간 인식 + 게임

```bash
cd ~/doosan_janggi_ws/janggi
./setup_venv.sh                 # 처음 한 번 (torch CUDA 포함 약 6 GB)
./realtime_ui/run.sh            # RealSense
./realtime_ui/run.sh --source 0              # 웹캠 / 동영상·이미지 파일 경로도 가능
./realtime_ui/run.sh --conf 0.4 --piece-height 15
```

카메라를 쓰는 다른 프로그램(보정 도구, realsense-viewer)은 먼저 끈다.

현재 기본 모델은 `models/weights.pt` (`janggi_dol` 1클래스)다.
말 위치·신뢰도·교차점만 표시하고 진영·종류를 분류하지 않는다. 화면에는 중립색의 `알`로 표시한다.
이 모델에서는 게임 조작을 비활성화하고, `--robot`을 전달해도 로봇에 연결하지 않는다.
`--model-mode`로 인식 방식을 선택한다. 옵션을 생략하면 기존 기본 경로 `models/weights.pt`를 사용한다.

| 옵션 | 모델 | 인식 내용 |
|---|---|---|
| 옵션 생략 | `models/weights.pt` | 현재는 말 위치만 |
| `--model-mode piece` | `models/weights_only_piece.pt` | 말 위치만 |
| `--model-mode full` | `models/weights_14class.pt` | 말 위치 + 진영·종류 (14클래스) |
| `--model-mode hybrid` 또는 `cnn` | `weights_only_piece.pt` → `models/piece_classifier/best.pt` | 위치 YOLO → MobileNetV3-Small 별도 분류 |

다른 모델 파일은 기존 `--model /경로/모델.pt`로 직접 지정할 수 있다.
`--model-mode`와 `--model`은 동시에 지정하지 않는다. 전환은 프로그램 재실행 시 적용한다.

```bash
./realtime_ui/run.sh --source ../tools/captures/video_20261109_223727_753138/color.mp4 --playback-fps 30
./realtime_ui/run.sh --model-mode full --source ../tools/captures/video_20261109_223727_753138/color.mp4 --playback-fps 30
./realtime_ui/run.sh --model-mode full --robot --robot-vel 30
```

옵션을 생략하면 기존처럼 속도 제한 없이 동영상을 처리한다.
`--playback-fps`를 지정하면 재생 속도를 제한한다. 30 FPS 파일을 15로 설정하면 절반 속도로 재생한다.

```bash
./realtime_ui/run.sh --source /경로/color.mp4 --playback-fps 15
./realtime_ui/run.sh --source /경로/color.mp4 --playback-fps 30
./realtime_ui/run.sh --source /경로/color.mp4 --playback-fps 0  # 속도 제한 없이 처리
```

카메라·사진에는 이 옵션을 적용하지 않는다. 추론이 지정한 FPS보다 느리면 실제 재생도 느려지며,
프레임을 건너뛰지는 않는다. 화면의 FPS는 실제 인식 처리 속도다.

## 인식 개수 기록

저장한 두 영상과 CSV를 동기화해 재생하고 분석 영상으로 내보내려면
[비전 로그 분석 뷰어](../../tools/EVALUATION_VIEWER.md)를 사용한다 (`./tools/run_evaluation_viewer.sh`, 워크스페이스 루트에서 실행).

`--log-counts`를 추가하면 화면 갱신과 별개로 **추론한 모든 프레임**의 개수를 CSV에 저장한다.
옵션을 생략하면 기록하지 않는다. 실제 말 수가 고정된 구간을 사용하며 기본 비교 기준은 32개다.

```bash
./realtime_ui/run.sh --model-mode piece \
  --source ../tools/captures/video_20261109_223727_753138/color.mp4 \
  --playback-fps 30 --log-counts --expected-pieces 32
```

저장 위치는 `janggi/realtime_ui/evaluations/counts_날짜_시간/`이며 Git에서 제외된다.
실행마다 새 폴더를 만들어 네 파일을 함께 저장한다.

- `counts.csv`: 원본 검출 수, 중복 제거 수, 판 할당 수, 안정화된 판의 말 수, 기준 개수 일치 여부.
  현재 신뢰도 기준·판 영역 자르기 사용 여부도 각 행에 남긴다.
- `counts.summary.json`: 종료 시 평균·최소·최대 개수, 기준보다 적거나 많은 프레임 수,
  **기준 개수와 정확히 일치한 프레임 비율**을 집계한다. 예: `metrics.deduplicated.equal_expected_fraction=0.95`는
  중복 제거 후 개수가 32개인 프레임이 95%라는 뜻이다. 터미널에도 비율과 파일 경로를 출력한다.
- `overlay.mp4`: 왼쪽 영상의 박스·신뢰도·격자가 그려진 결과.
  첫 overlay의 실제 크기로 저장하므로 좌우 검정 여백을 추가하지 않는다.
  화면의 `판 확대`, `상세` 설정을 따라간다. 녹화 중 확대 설정을 바꿔 화면 비율이 달라지면
  고정된 저장 크기에 맞춰 비율을 유지하며 중앙을 잘라낸다. 전체 영역을 유지하려면 녹화 중 확대 설정을 유지한다.
- `board.mp4`: 오른쪽 **실시간 인식판**을 별도 영상으로 저장한다.
  화면과 같은 렌더러로 안정화된 인식 결과를 그린다. 게임 모드의 수동 이동·선택 표시나 버튼·기보 영역은 포함하지 않는다.

두 동영상의 첫 프레임(0번)은 CSV의 `frame=1`에 대응한다. 추론마다 두 영상에 각각 한 프레임을 저장하므로
UI가 표시를 건너뛰어도 로그와 영상의 프레임 수는 일치한다. 창이 가려지거나 최소화돼도 화면 캡처 없이 저장한다.
동영상 입력은 `--playback-fps`가 지정되면 그 FPS로, 생략/0이면 원본 FPS로 MP4를 저장한다.
카메라·사진 또는 원본 FPS를 알 수 없는 경우에는 30 FPS를 사용한다.
실제 추론 속도가 느려도 MP4는 지정된 고정 FPS로 재생된다. 원본 시점은 CSV의 `source_frame`/`source_time_s`를 참고한다.
요약 JSON의 `metadata.videos`에 파일 경로·FPS·크기·프레임 수를 남긴다.
종료할 때 두 MP4를 마무리하므로 창을 정상 종료한 뒤 파일을 연다. `--log-counts`가 없으면 영상도 저장하지 않는다.

보정이 없으면 판 할당 관련 값은 미측정(빈 CSV 값/요약 비율 null)이다.
CSV는 처리 순서와 별도로 동영상의 원본 프레임 번호(`source_frame`, 0부터),
원본 FPS 기준 시각(`source_time_s`), 반복 횟수(`source_loop`, 첫 재생은 0)를 기록한다.
UI에서 영상을 반복 재생하면 기록도 이어지며 요약은 기록한 전체 프레임을 대상으로 한다.
한 번 재생한 부분만 비교하려면 `source_loop=0`인 행을 사용한다.
카메라 입력에는 원본 동영상 프레임 번호·시각이 없다.

이 비율은 **개수 충족률이며 Recall이나 검출 정확도가 아니다.**
실제 말 하나를 놓치고 배경 하나를 오검출해도 32개가 될 수 있다.
잡힌 말을 치워 실제 개수가 줄어드는 영상에서는 전체 구간을 32개 기준으로 평가하면 안 된다.
모델 비교 시 동일 영상·구간과 입력 설정을 사용하고, 기록 도중 신뢰도 기준을 바꾸지 않는 것이 좋다.
요약에는 사용한 모델 경로·SHA-256과 주요 설정도 남긴다. 프로그램 창을 정상 종료하면 요약 파일이 저장된다.

신뢰도(conf)도 같은 CSV에 프레임별로 저장한다. 값의 범위는 0~1이다 (`0.88` = 88%).

| CSV 열 | 의미 |
|---|---|
| `conf_count` | 통계에 포함한 검출 박스 수 |
| `conf_mean` | 전체 검출 박스 conf 평균 |
| `conf_min` | 가장 낮은 conf |
| `conf_p30` | 30백분위 값(P30, 선형 보간): 하위 약 30%의 경계 |
| `conf_bottom30_count` | 하위 30% 평균에 포함한 박스 수 |
| `conf_bottom30_mean` | conf가 낮은 순으로 `ceil(검출 수 × 0.3)`개를 고른 평균 |

32개를 검출했다면 하위 30% 평균은 가장 낮은 10개의 평균이다.
위 열들은 중복을 포함한 원본 검출 기준이며, **중복 제거 후의 같은 통계**는 `dedup_conf_` 접두사로 함께 저장한다.
예: `dedup_conf_mean`, `dedup_conf_min`, `dedup_conf_p30`, `dedup_conf_bottom30_mean`.
검출이 없는 프레임은 개수 0, 신뢰도 평균·최소·P30·하위 평균은 빈 값이다.

요약 JSON의 `confidence.raw`와 `confidence.deduplicated`에는 전체 검출 표본의 평균·최솟값을 기록한다.
`mean_frame_p30`과 `mean_frame_bottom30_mean`은 **검출이 있는 프레임별 통계의 평균**이며,
전체 표본을 한꺼번에 모은 P30이나 하위 30% 평균은 아니다.
통계에는 설정한 신뢰도 기준을 통과한 검출만 들어간다. 미검출된 말은 conf 0으로 포함되지 않으므로 개수 지표와 함께 비교한다.

## 화면

**왼쪽 — 카메라 + 인식 결과**

- 박스 색: 위치 전용 모델은 청록색, 기존 모델은 파랑 = 초·빨강 = 한. 회색은 교차점에 할당되지 않은 검출
- 라벨: 말 글자 + 신뢰도(%). `상세`를 켜면 할당된 교차점 좌표도 표시
- 노란 점·선: 장기판 교차점과 테두리 (보정 파일 기준). 박스와 교차점을 잇는 선이 할당 결과
- `판 확대`: 판 영역만 잘라 크게 보여준다 (기본 켜짐)
- 아래 줄: 인식 FPS, 원본 검출 수, 중복 제거 후 검출 수, 판에 할당된 수. 영상이 멈추면 경고
- `중복 제거`는 클래스와 무관하게 IoU(박스 겹침 비율)가 0.5 이상인 박스 중 신뢰도가 높은 박스만 남겨 계산한다.
  교차점에 할당되지 않은 박스도 포함한다. 표시용 수치이며 실제 박스 표시·판 할당 결과는 바꾸지 않는다.

**오른쪽 — 장기판**

| 모드 | 내용 |
|---|---|
| 실시간 인식 | 인식된 판 상태 (최근 8프레임 다수결로 안정화) |
| 게임 | 인식된 판에서 시작해 말을 둔다 |

게임 모드 조작:

- 자기 차례 말을 클릭하면 둘 수 있는 칸이 보라색 점(잡을 수 있는 말은 점선 원)으로 표시된다. 그 칸을 클릭하거나 말을 끌어다 놓으면 둔다.
- 차례, 장군, 외통을 위쪽에 표시한다. 기보는 오른쪽 목록에 쌓인다.
- `인식된 판으로 새 게임`: 지금 인식 결과로 시작. 위쪽 진영은 궁 위치로 정한다. `선수`로 먼저 둘 진영을 고른다 (기본 초).
- `판에서 둔 수 읽기`: 사람이 실제 판에서 말을 옮긴 뒤 누르면, 게임 판과 인식 결과의 차이로 그 수를 찾아 규칙을 확인하고 반영한다.
- `되돌리기`(Ctrl+Z), `한수쉼`
- `인식된 판으로 맞추기`: 차례·기보는 두고 판만 인식 결과로 덮어쓴다 (인식 오류를 실제 판에서 바로잡은 뒤 등).
- `인식과 다른 칸 표시`: 게임 판과 실제 판이 다른 칸을 주황색 원으로 표시한다.

규칙(`rules.py`): 궁·사 궁성 이동, 차 직선·궁성 대각선, 포 넘기(포는 넘거나 잡지 못함), 마·상 멱(막힘), 졸·병 전진·옆·상대 궁성 대각선, 자기 궁이 잡히는 수 금지. 빅장·점수·반복수는 다루지 않는다.

## 위치 YOLO + 별도 CNN 분류

학습 및 결과 확인은 [분류기 학습 안내](../../tools/PIECE_CLASSIFIER.md)를 참고한다.

```bash
# 워크스페이스 루트에서 실제 카메라
./janggi/realtime_ui/run.sh --model-mode hybrid

# 촬영 영상으로 확인
./janggi/realtime_ui/run.sh --model-mode hybrid \
  --source tools/captures/video_20261109_223623_956498/color.mp4 --playback-fps 30

# 다른 학습 결과 선택
./janggi/realtime_ui/run.sh --model-mode hybrid --classifier models/my_classifier/best.pt
```

`--classifier-conf 0.5`는 종류 확정 기준이고 `--conf`/슬라이더는 YOLO 검출 기준이다.
오버레이의 `D90/C85`는 탐지 90%, 종류 분류 85%를 의미한다. 분류 미달/프레임 밖 Crop은 `알`로 표시하고
그 위치를 유지한다. 종류 미확정 말이 있는 상태에서는 인식판으로 게임 시작·동기화·착수 읽기를 막는다.
14종이 없는 부분 분류 모델에서는 로봇 옵션을 비활성화한다.
`--log-counts`의 기존 conf 통계는 계속 **YOLO 검출 확률**이다. hybrid에는 별도
`classifications.jsonl`을 추가해 프레임별 박스·탐지 확률·분류 확률·라벨을 저장한다.

`--classifier-backend mobilenet`이 기본이다. 같은 전체 RGB Crop 전처리로 학습한 Ultralytics 분류 모델은
`--classifier-backend ultralytics --classifier /경로/best.pt --classifier-size 224`로 교체할 수 있다.
이는 위치 탐지 가중치가 아닌 **Classification** 가중치여야 한다. MobileNet 학습 체크포인트와 호환되는
파일 형식은 아니며, 클래스 이름은 `blue_cha`, `red_soldier` 등의 규약이어야 한다.
분류기는 `predict(images)` 인터페이스로 분리되어 향후 다른 모델 어댑터도 추가할 수 있다.

## 화면 방해 상태와 박스 크기 표시

영상 아래의 **화면 방해** 표시를 확인한다. **hybrid/cnn**에서는 전역 방해 중에도 정상 객체의 종류 분류는 계속하며,
안정된 게임판의 이동·포획 확정만 보류한다. 각 말의 MOVE/MISS/CONF/SIZE가 있으면 그 말의 종류·크기 갱신은 멈춘다. piece/full 모드에서는 상태 표시 기능으로 동작한다.

- **방해 의심**: 판 영역에서 움직임을 감지하거나, 최근 검출/판 할당 수가 감소·증가를 반복하거나,
  마지막 안정 기준보다 검출 또는 판 할당이 2개 이상 줄었을 때
- **안정 확인 중**: 의심 신호가 사라진 뒤 기본 0.8초 동안 안정 여부를 확인 (최소 3개 관측 필요)
- **방해 징후 없음**: 현재 휴리스틱에서 움직임·개수 진동이 보이지 않을 때
- **판단 불가**: 검출/할당이 없거나 보정 영역이 화면 밖인 경우. 영상이 오래 지연되어도 판단 불가로 표시

보정 파일이 있으면 네 모서리 안의 장기판 영역만 움직임을 확인하고, 없으면 전체 화면을 본다.
최대 변 320px로 축소한 흑백 영상의 프레임 차이(20 이상)를 사용하며, 영역의 기본 3% 이상이 변하면 움직임이다.
최근 기본 2초 안의 개수 변화 방향이 뒤집히면 진동으로 본다. 한 번의 32→31 감소만으로 진동으로 판단하지 않는다.
영상 반복, 검출 신뢰도 설정 또는 ROI 사용 여부 변경 시 기준을 다시 수집한다.

이는 **손/로봇팔 전용 탐지기가 아니다.** 조명 변화·카메라 흔들림·정상 착수도 의심으로 표시될 수 있으며,
처음부터 정지한 손으로 가린 화면은 감지하지 못할 수 있다. 여러 말이 정상적으로 제거된 뒤 개수 감소 경고가
유지되면 실제 판을 확인한 후 **방해 기준 다시 잡기**를 누른다. 고정 32개를 정상 기준으로 강제하지 않는다.

**박스 표시** 콤보박스에서 다음을 선택한다. 선택한 값은 저장되는 overlay 영상에도 적용한다.

- **신뢰도**: 기존 YOLO 확률. 2단계 모드는 `D90/C85` 형식으로 탐지/분류 확률 표시
- **크기(px)**: 검출 박스의 원본 영상 기준 가로×세로 픽셀 수
- **크기(mm)**: 박스 좌우/상하 변 중점을 말 윗면 평면으로 투영한 뒤 실제 좌표에서 구한 가로×세로 추정값 (`~` 표시)
- **기하평균(px)**: 원본 박스의 `√(가로×세로)`
- **기하평균(mm)**: 말별 유효 크기 관측의 중앙값. 아직 이력이 없으면 현재 박스의 추정값 표시

mm는 말의 정확한 지름이 아닌 **YOLO 박스의 추정 길이**다. 보정 당시와 카메라·판 배치가 같아야 하며,
`--piece-height`(기본 12mm)를 사용한다. 입력 해상도가 보정 해상도와 다르거나 변환을 사용할 수 없으면
`px (mm N/A)`로 대체한다. 판 확대 화면에 맞춰 늘어난 픽셀 수가 아니다.

```bash
./realtime_ui/run.sh --model-mode hybrid --box-label size-mm
# 감지 민감도/시간 조절 예시: 움직임 면적 5%, 관측 창 2초, 안정 대기 1초
./realtime_ui/run.sh --obstruction-motion 0.05 --obstruction-window 2 --obstruction-settle 1
```

## 적응형 비동기 분류와 통합 말 객체

hybrid/cnn은 위치 YOLO를 매 프레임 실행한다. 종류 분류는 별도 스레드에서 객체별 필요에 따라 실행하며,
이미 종류를 알고 정상인 객체는 기본 **0.5초 간격**, 미분류 객체는 **즉시/최신 프레임 우선**으로 처리한다.
처리 시간이 길어져도 요청을 쌓지 않고 최신 프레임만 예약한다. 보정 파일이 없어도 영상 좌표 기반의
객체 연결과 종류 분류가 동작하며, 이 경우 교차점·게임 판정과 mm 크기 보조는 사용하지 않는다.

```bash
./realtime_ui/run.sh --model-mode hybrid --classification-interval 0.5 --box-label geometric-mm
# 부하가 크면 분류 간격 늘리기
./realtime_ui/run.sh --model-mode hybrid --classification-interval 0.8
# 판 밖/격자에 맞지 않는 배치까지 전체 화면으로 보기: UI의 판 확대도 해제한다.
./realtime_ui/run.sh --model-mode hybrid --full-frame --show-piece-motion
```

### 객체는 검출 기준, 교차점은 선택 속성

예전의 S1 센서와 piece_0001을 **한 종류의 PieceState 객체**로 통합했다. 영상 추적과 게임 인덱스는
동일한 객체를 참조하며 같은 말의 두 분류 이력을 따로 만들지 않는다.

- 검출되면 `piece_0001` 같은 ID로 생성하고 영상 박스·현재 검출 여부·연결 신뢰도를 보관
- 종류별 확률·확정 종류·분류 이력·크기 이력·MOVE/MISS/CONF/SIZE를 같은 객체에 보관
- `board_assigned=true`이면 `cell=[x,y]`, 미할당/미검출이면 `cell=null` (`[-1,-1]` 사용 안 함)
- `confirmed_cell`은 별도로 확인한 게임 위치. 현재 영상 위치와 같다고 가정하지 않음
- 미검출은 포획을 의미하지 않음. 보이지 않는 말의 기억 위치를 실시간 화면에 그리지 않음

박스 겹침·중심 거리·크기로 연결하므로 교차점 밖에서도 동작한다. 애매한 연결에서는 새 ID가 생길 수 있다.
가림 후 같은 외형의 말이 교차하면 영상만으로 영구 신원을 보장할 수 없다. 안정된 게임 전이로 연결이 확인되면
기존 ID/이력을 현재 시각 추적에 연결하고 `identity_reconciled` 이벤트를 남긴다.

### MISS 휴면과 재등장 확인

미검출 객체는 **시간 제한 없이 현재 실행 세션의 휴면 객체**로 보관한다. 미검출만으로 포획/사망 처리하거나
실시간 판에 기억 위치를 그리지 않는다. 영상 반복·입력/인식 설정 변경에 의한 초기화 및 프로그램 종료는 별도이다.
`MISS` 경고 사각형의 표시 시간은 기존처럼 마지막 관측 후 최대 2초이며, 객체 보관 시간과 무관하다.

현재 추적 중인 말의 연결을 우선한다. `good_box`의 가로세로 비율과 정상 크기 이력의 중앙값으로
추적 기준 박스를 구성한다. SIZE/CONF로 부분 박스가 작아져도 기준을 축소하지 않는다.
현재 검출과 기준 박스의 포함 정도·중심 거리를 비교하며, 작은 부분 박스 때문에 MOVE 판정이 과장되지 않게
이동량도 정상 크기로 나눈다. **추적 중심은 MOVE 판정 여부와 무관하게 매 검출마다 갱신**한다.
부분 가림 중 아주 천천히 움직여도 기준점이 과거 위치에 남지 않으며, 기준 크기와 종류 이력은 따로 보존한다.
MOVE/CONF/SIZE 중에도 ID와 이미 알려진 종류는 유지하며, 새 종류·mm 크기 누적은 정상 관측이 돌아올 때까지 보류한다.

- MISS 후 기존 위치 주변에 유일한 후보가 보이면 **첫 재검출 프레임에 기존 ID/종류를 임시 연결**한다.
  완전히 복구되기 전의 CONF/SIZE 부분 검출도 연결 가능하다. 누락 직전 중심과 정상 크기를 기준으로
  사방에 정상 크기의 35% 여유를 둔 `missing_box`와 누락 시각 `missing_since`를 저장한다.
  해당 누락 영역과 작은 쪽 박스 면적의 60% 이상 겹치고, 중심 거리가 정상 크기의 0.95배 이하인 후보 등을 확인한다.
  누락 영역은 해당 MISS 동안 고정하고 다음 누락이 발생하면 최신 추적 위치에서 다시 저장한다.
- 여러 과거 ID나 여러 검출이 비슷한 후보이면 억지로 연결하지 않는다. 포획/병합된 객체는 후보에서 제외한다.
- 임시 연결은 `revival_state=tentative`. 화면에는 기존 종류를 즉시 표시하되 확정 게임판 갱신에는 사용하지 않는다.
- 정상 관측에서 독립 CNN 결과 두 번이 같은 기존 종류를 확률 0.6 이상으로 지지하면 연결을 확정한다.
  다른 종류를 두 번 연속 확률 0.8 이상으로 지지하면 **같은 ID의 종류를 수정**하고 과거 확률·mm 크기 이력을
  새 관측으로 재구성한다. 이전 이력은 수정 이벤트에 남겨 추적할 수 있다.
- 국소 방해나 불확실한/서로 다른 분류 결과가 끼면 사후 검증 횟수를 다시 쌓는다.
  종류 이력이 없는 객체는 정상 관측 5회 이상/0.3초 이상이면 기하학적 재연결을 확인한다.

`current_state.json`에는 `status=dormant`, `tracking_center`, `good_box`, `revival_state`,
`missing_box`, `missing_since`, `revival_count`, `last_revival`을 저장한다. `events.jsonl`에는 `dormant`, `revival_attached`,
`revival_probe`, `revival_verified`, `revival_reclassified`를 기록한다.
동일 위치에서 말을 교환한 경우 영상만으로 실제 물리 신원을 구분할 수는 없으며, 이 정책은 위치 연속성을 우선한다.
32개 고정·종류별 개수 제한이나 다른 객체와의 역할 교환은 적용하지 않는다.
시간으로 자동 삭제하지 않으므로 긴 세션에서 신규 ID가 많이 생기면 상태 파일과 휴면 객체 수도 늘어난다.
재실행 시 과거 세션을 자동 복원하지는 않는다.

### 연속 추적: 위치 예측과 전체 배정

최근 검출 이동량으로 속도를 평활 추정하고 다음 위치를 예상한다. 가려진 박스는 속도 반영을 줄이고,
예측 시간은 최대 0.3초/변위는 정상 크기 1배로 제한한다. 예측만으로 보이지 않는 말을 화면에 생성하지 않는다.
종류 예측은 연결 점수에 섞지 않으며 정상 크기 박스·현재 위치·예측 위치로 연결 후보를 만든다.

현재 활성 객체와 높은 신뢰도 검출을 먼저 **전체 최소 비용 배정(Hungarian)**하고, 남은 활성 객체에만
낮은 신뢰도 검출을 같은 방식으로 배정한다. 단독 후보는 동일한 최적 해를 바로 선택해 계산을 줄인다.
휴면 객체는 저장된 MISS 영역에서 후보가 유일한지 확인하고 임시 연결한다. 완전히 겹친 동일 외형의 말은
위치만으로 구분을 보장하지 못한다.

hybrid/cnn에서는 YOLO를 두 번 실행하지 않고 기본 `--tracking-low-conf 0.1`까지 한 번 검출한다.
기존 `--conf` 이상 검출이 우선이며, 그 아래의 박스는 **기존 ID 연결에만** 사용한다.
낮은 신뢰도 박스로 새 객체를 생성하거나 종류·크기 이력을 갱신하지 않는다.
이 관측은 `tracking_only=true`/CONF로 표시하고 기존 종류를 유지한다. 정상 복귀 후에만 새 분류를 반영한다.
추적 보조 박스는 원래 검출 개수/신뢰도 통계와 확정 게임판 증거에서 제외하며 화면과 classifications 로그에는 남긴다.

`current_state.json`에 `tracking_velocity`와 `tracking_only`가 기록된다.
새 ID 발생은 `created` 이벤트의 박스·신뢰도·시각으로, 누락과 재연결은 `dormant`/`revival_attached`로 확인한다.
이 이벤트 수는 추적 진단값이며 실제 ID 교환 횟수는 정답 궤적과 비교해야 평가할 수 있다.
32개 또는 종류별 개수 제약은 사용하지 않는다.

### 실시간 처리 비용

추적 연결은 각 말의 기준 박스/정상 크기와 각 검출의 좌표 수치를 프레임당 한 번 계산해 재사용한다.
2단계 모드에서 이미 중복 제거한 검출에 NMS를 다시 수행하지 않으며, 정상 분류 대상이 없어지면 대기 중인
분류 예약을 취소한다. 실행 중인 작업의 결과는 기존처럼 객체별 세대 번호로 검증한다.
RGB 프레임에서 각 Crop을 추출할 때 전체 프레임의 중복 RGB 복사를 생략하며, 보간/회전/정규화는 동일하다.
분류와 재연결 검증 관측 이벤트는 모두 기록하되, `revival_probe`/`classification_preview`만으로 전체 상태 JSON을 매번 다시 쓰지 않는다.
상태 스냅샷은 기본 1초 간격이고 연결 확정/종류 수정/이동/포획 등 주요 이벤트와 종료 때는 즉시 저장한다.
분류 주기와 방해 판정·ID 연결 임계값은 성능 최적화를 이유로 완화하지 않는다.

### 미분류 객체의 긴급 복구

ID가 새로 생기거나 종류가 비어 `알`로 표시되는 객체는 MOVE/CONF/SIZE·초기 안정화 대기 중에도
CNN을 우선 실행한다. 원시 분류 최고 확률이 **50% 이상(경계 포함)**이면 즉시 예비 종류를 표시하고,
50% 미만이면 알을 유지하며 다음 최신 프레임으로 계속 재시도한다. 이 표시 기준은 `--classifier-conf`와 별도이다.

방해 중의 긴급 결과는 `preview_label`/`preview_confidence`에만 보관하며 정상 확률 이동평균·mm 크기·게임판
확정 증거에는 섞지 않는다. 정상 관측이 확보되면 일반 분류/기존 재연결 검증을 통해 정식 종류를 갱신한다.
이미 알려진 종류는 방해 중에도 유지한다. 알려진 객체의 갱신 주기는 `--classification-interval`로 조절한다.

알인 객체만 매 프레임 예약 후보가 되며, 비동기 실행기는 0.5초 대기보다 긴급 작업을 우선한다.
모델 실행 중에는 최신 요청 하나만 보관하므로 모든 영상 프레임의 분류를 보장하지는 않는다.
정기 갱신 시점이 된 정상 객체도 함께 배치에 넣어 미분류 객체 때문에 갱신이 계속 밀리지 않게 한다.
상태 파일은 정식 `label`과 예비/표시 `preview_label`/`display_label`을 구분하며 긴급 관측은
`classification_preview` 이벤트로 기록한다. 예비 분류가 틀릴 수 있으므로 게임 확정에는 정상 검증을 요구한다.

### 객체별 분류 갱신

정기 분류는 전역 화면 방해가 있어도 **현재 검출되고 로컬 MOVE/MISS/CONF/SIZE가 없는 객체**에 대해 수행한다.
미분류 객체의 긴급 표시 복구는 위의 별도 경로를 사용한다.
각 객체의 초기 정상 관측 최소 3개와 연결 신뢰도를 확인하며, 의심 객체는 크기 수집/가중치/확률 누적을 모두 보류한다.
비동기 결과도 객체별 세대 번호와 현재 박스를 다시 확인한다. 도중에 방해받은 말의 오래된 결과만 버리고
정상인 다른 말의 결과는 적용한다. 로봇 동작 중에도 이 객체별 기준을 사용하며 게임 확정은 기다린다.

크기 점수로 현재 CNN 확률을 먼저 보정한 뒤 **과거 80% + 현재 20%**로 결합한다.
다른 종류가 연속 3회 우세하고 누적 확률이 기준 이상이어야 확정 종류를 바꾼다.
`--classifier-conf`는 첫 종류 확정/변경 및 이동 목적지 확인 기준이다. 이미 확정된 종류는
단 한 번의 낮은 확률로 지우지 않는다. 오버레이 C는 융합 확률이며 CNN 단독 확률과 다를 수 있다.
현재 CNN의 최고 종류·확률은 객체 history와 classification 이벤트에 남긴다.

유효 관측의 `√(가로mm×세로mm)` 최근 최대 20개 중앙값을 사용한다. 5개 이상 모이면 중앙값에서
`max(2mm, 3×1.4826×MAD)`를 넘는 측정을 제외한다. 작은 말(사·졸·병) 23mm, 중간 말(차·포·마·상)
29mm, 궁 35mm에 가까운 종류를 부드럽게 우대하며 다른 그룹의 확률을 0으로 만들지는 않는다.
크기 퍼짐이 크면 가중치를 약화하고, 유효한 mm 보정이 없으면 적용하지 않는다.
`--size-strength 0`으로 크기 가중치를 끄고 `--history-alpha 0.2`로 현재 관측 비중을 정한다.

### 게임 스냅샷과 이동·포획

실시간 인식판은 **현재 검출된 객체를 교차점에 투영한 결과**다. 게임은 별도의 마지막 확정 배치
스냅샷을 사용하므로, 전역 방해 중 라이브 객체의 종류/위치가 바뀌어도 게임판을 즉시 바꾸지 않는다.
보정이 있고 전역 안정 조건을 통과하며 현재 판의 객체들이 유효하게 관측된 뒤,
서로 다른 분류 관측에서 같은 변화를 2회 확인한다.

- **일반 이동**: 개수 유지, 출발지 1곳이 비고 빈 목적지 1곳이 채워짐. 현재 목적지가 출발 말과 일치하고 합법 이동인지 확인
- **포획**: 개수 1 감소, 출발지 1곳이 빔. 상대 말이 있던 목적지가 출발 말로 교체됐다는 현재 분류 증거를 확인
- 개수만 하나 줄고 교체 증거가 없으면 포획으로 확정하지 않음
- 차례와 로봇의 계획 출발/목적지를 대조하고, 관찰 자세 복귀 후 새 판독으로 로봇 착수 성공을 확인
- 포획 확인 시 출발 ID와 이력을 목적지에 연결. 목적지의 잠정 시각 연결로 상대 이력이 섞였으면 마지막 확정 이력으로 복원한 뒤 captured 기록
- 한 수로 설명되지 않는 안정 배치가 반복되면 게임 세대와 확정 배치만 초기화한다. 모든 시각 객체의 ID·종류 확률·크기·분류 이력은 보존하고 게임 배치를 다시 확인한다. 영상 반복/입력 설정 변경에 의한 전체 초기화는 별도이다.

종류 예측의 흔들림만으로 재배치를 확정하지 않는다. 재인식 후 이전 대국과 연결이 끊기면 새 게임을 시작한다.
전역 개수 감소 경고가 지속되는 동안에도 정상 말의 분류는 계속하지만 게임 자동 확정은 하지 않는다.
실제 판을 확인한 뒤 **방해 기준 다시 잡기**로 전역/로컬 기준을 새로 수집할 수 있다. 이 버튼은 객체의
종류 이력 자체를 지우지는 않는다. SIZE 중에 누르면 잘못된 mm 크기 누적도 함께 비운다. 영상 반복·ROI/검출 설정 변경은 새 인식 세대로 초기화한다.

### 저장 위치

`--log-counts`와 관계없이 hybrid/cnn은 다음 세션 폴더를 만든다.

```text
janggi/realtime_ui/states/session_날짜_시간/
├── session.json          # 모델·보정·입력·분류 주기·통합 객체 모델 정보
├── calibration.yaml      # 사용한 보정 파일 사본 (파일이 있을 때)
├── current_state.json    # 전체 객체와 별도 확정 게임판 스냅샷 (schema_version=2)
└── events.jsonl          # 분류·이동·포획·재연결·크기 기준 재구성·재인식
```

상태 파일의 `pieces`에는 미할당 객체도 포함한다. `board`는 확정 게임판이며 각 행에 확정 종류도 저장한다.
`visible_count`는 현재 보이는 말 수, `expected_count`는 확정 게임판 말 수다. 두 값은 다를 수 있다.
기본 1초마다 원자적으로 저장하고 이동/포획/재인식/종료 시에도 저장한다.
전체 이벤트는 JSONL, 객체별 최근 분류 20개·크기 20개·이동 50개는 상태 파일에 보관한다.
`--state-dir /원하는/상위폴더`로 경로를 바꿀 수 있다. 재실행 때 이전 상태를 자동 적용하지 않고 실제 판을 새로 확인한다.
`states/`는 Git에서 제외된다. classifications.jsonl에도 동일한 통합 ID와 융합 확률·크기를 기록한다.

## 말별 국소 움직임·방해 영역 표시 (실험)

영상 아래 **말별 방해 영역(실험)** 체크박스로 켜고 끈다. 기본은 꺼짐이며,
처음부터 표시하려면 `--show-piece-motion`을 사용한다. piece/full/hybrid 모두 동작한다.

```bash
cd ~/doosan_janggi_ws/janggi
./realtime_ui/run.sh --model-mode hybrid --device cuda:0 \
  --source ../tools/captures/video_20261109_223623_956498/color.mp4 \
  --playback-fps 30 --show-piece-motion --log-counts
```

90개 교차점 대신 **YOLO가 찾은 말 박스 하나하나를 센서로 사용**한다. 위치/박스 겹침으로 짧은 구간의
통합 객체 ID를 연결하므로 보정 파일, 교차점 할당, 종류 확정 여부와 무관하게 관찰한다.
판 영역만 인식 중이면 그 ROI 안의 말만 대상이다. 판 밖까지 실험하려면 **판 영역만 인식**을 끄거나
`--full-frame`을 지정한다. 영역에도 동일한 `piece_0001` ID를 표시한다. 영상 연결은 추정이므로 영구 신원을 보장하지 않는다.

| 표시 | 조건 | 의미 |
|---|---|---|
| 노란색 `MOVE` | 최근 0.3초 또는 직전 관측 대비 중심 이동이 박스 기하평균의 20% 이상 | 말 주변의 이동 |
| 빨간색 `CONF` | 안정 기준 중앙값 대비 YOLO 신뢰도 0.15 이상 하락 | 탐지 확률 급락 |
| 빨간색 `SIZE` | 박스 기하평균 픽셀 크기가 기준 대비 25% 이상 변화 | 박스 축소/확대 |
| 빨간색 `MISS` | 최근 보이던 말이 연속 2개 처리 프레임에서 검출되지 않음 | 마지막 관측 영역의 검출 누락 |

기준값은 말별 정상 관측 최대 20개의 중앙값을 사용하며, CONF/SIZE는 최소 3개의 정상 관측 이후 판단한다.
의심 중에는 해당 센서의 기준 신뢰도·크기를 갱신하지 않는다. MOVE/CONF/SIZE는 마지막 이상 관측 이후
0.5초간 유지해 깜빡임을 줄인다. MISS는 재검출하면 해제하며, 마지막 관측 후 최대 2초까지만 표시한다.
MISS 사각형은 누락 위치를 알려주는 표시이며, 말이 현재 그곳에 있다고 추정해서 그리는 것은 아니다.
센서 연결이 애매하거나 말이 빠르게 멀리 이동하면 새 센서 ID가 생길 수 있다.

전역 방해 중에도 말별 분석은 계속한다. **hybrid/cnn에서는 로컬 신호가 있는 객체만 종류·크기 갱신을 멈춘다.**
영역 체크박스는 표시만 제어하며 꺼져 있어도 이 판정은 동작한다. piece/full은 기존 표시 실험 동작을 유지한다.
게임 이동·포획은 여전히 별도 안정화 전후 판으로 판단한다. 정상 이동·포획도 이 영역에 나타날 수 있고,
손/팔의 정확한 윤곽을 분할하는 기능은 아니다. 말이 없는 곳이나 처음부터 검출되지 않은 말 주변은 판단할 수 없다.

현재 프레임의 의심 박스에 반투명 색을 표시하고, 켜져 있으면 저장되는 `overlay.mp4`에도 동일하게 표시한다.
hybrid의 `classifications.jsonl`에는 `piece_motion_regions`로 센서 ID·박스·원인·기준값을 추가 기록한다.
보조 상태 파일이나 가상 장기판 `board.mp4`에 가려진 말을 추가하지 않는다.
hybrid/cnn의 표시 체크박스를 껐다 켜도 객체·기준·종류 이력은 유지한다. 영상 반복·인식 설정 변경이나
방해 기준 다시 잡기에서는 센서 기준을 다시 수집한다. piece/full은 표시를 다시 켤 때 기준도 새로 수집한다.

```bash
# 민감도 조절: 신뢰도 하락 0.2, 크기 변화 30%, 이동 거리/크기 0.25
./realtime_ui/run.sh --show-piece-motion \
  --local-conf-drop 0.2 --local-size-change 0.3 --local-move-ratio 0.25
```


### SIZE 기준 복구

작게 가려진 박스가 초기 기준이 되면 정상 크기 복귀를 확대 이상으로 계속 판단하던 문제를 보완했다.
SIZE 진입은 기본 25%, 해제 쪽은 기본 20%(사용자 진입 기준의 80% 이하)로 구분한다. 단순 시간 초과로 경고를 지우거나 기준을 자동 축소하지 않는다.
SIZE만 남았고 MOVE/CONF/MISS가 없으며 탐지 확률이 `max(0.8, 기준 확률-0.05)` 이상일 때,
기준보다 크되 2배 이내인 박스를 복구 후보로 모은다. 가로세로 비율 1.6 이내, 최소 5개 관측,
최소 0.8초, 후보 크기 범위가 중앙값의 5% 이내라는 조건을 모두 확인한 뒤 기준을 재구성한다.
고FPS에서도 시간 조건이 사라지지 않도록 후보 시작 시각은 샘플 개수 제한과 별도로 보관한다.

복구 시 잘못된 작은 mm 누적만 비우고 종류 확률 이력은 유지하며, 이전 크기/확률을 `size_reference_rebuilt` 이벤트에 남긴다.
계속 작아진 박스, 낮은 신뢰도, 극단적인 크기 변화는 자동으로 정상으로 받아들이지 않는다.
이 경우 실제 화면을 확인하고 **방해 기준 다시 잡기**로 새 기준을 수집한다.
